# Making the same place survive a change of medium

## Intent and production choices

The story asks for a visible escape from a comic, followed by a photographic
shore ride and a quiet ending. Code owns the drawn character's acting, bicycle
mechanics, panel contact and tear timing. A generated background supplies the
painted environment. Image editing translates an actual rendered code frame into
photographic materials; H3 supplies feather, water and photographic camera motion.
The choices follow what each passage needs, not the words “animation” or “cinema”.

The initially independent comic and beach candidates matched the character but
not the location. `planning-image-prompts.json` and the corresponding
`comic-pelican` / `coast-pelican` Assets preserve that exploration. They are not
the final continuity anchors. The independent beach has a different setting and
light direction; copying those prompt descriptions as a matched pair would
repeat the problem.

## Inputs, their roles, and the actual outcome

1. `background-prompt.json` creates the empty painted harbour. Code adds the
   pelican, bicycle and movement. `comic-world-anchor.png` captures the actual
   scene at the tear-contact time without the paper occluding the world.
2. `image-edit.json` changes rendering/materials while asking to preserve the
   parapet, paving, village, tower, sailboats, ridge, wheel centres and rider.
   `photo-world-anchor.png` is the result. The paired comparison and
   `review/anchor-review.json` identify observed correspondences; they do not
   establish identical geometry.
3. `comic-world-motion.mp4` is a 97-frame, 24 fps code motion/layout guide.
   The first video request uses the photographic image for appearance/layout
   and this illustrated video for motion. Reference conditioning is not a strict
   first-frame guarantee. `video-requests.json` preserves the actual prompts,
   input ordering and generation settings without a deployment address or key.
4. The selected 209-frame ride is reviewed before the next request. Its actual
   frame 208 becomes `harbour-ride-exit`, alongside the shared photo anchor, for
   the second 209-frame clip. The cut is allowed to change shot size; landmark
   correspondence and the stopped rider's action matter more than pretending
   it reproduces a previous frame exactly.
5. Selected ride frames 0–33 become `same-world-entry-f0` through `f33`.
   The code's `entry000` through `entry033` bindings expose them during the tear
   at global frames 182–215. The next placement starts at ride frame 34.
   This is how the edit avoids replaying the newly exposed movement.

For another work, use only the references and control modes its model actually
supports. A usable image or video reference is not evidence that a provider
preserved an entire environment or an exact performance.

## Adapting the Project

The actual selected clips are imported Assets so rebuilding needs no model
request. To replace either clip, inspect its returned duration, movement,
camera, landmarks and light, then update the selected media and Project through
the normal authoring APIs. If the ride changes, regenerate its entry-frame
Assets and the ending-state image from the chosen footage; the current PNGs
refer to the included ride, not an interchangeable visual style.

Keep a deliberate distinction between a style change and a location change.
Here the harbour can recede as the camera travels toward the adjoining cove;
it should not disappear simply because the image becomes photographic. A
different story can intentionally change place, provided the edit communicates it.

`author/sound.mjs` produces 1,200,000 samples/channel at 48 kHz. The rip cue is
at frame 182 / 24 seconds on that shared timeline. Both generated clips keep
their original audio bytes, while the final placements select mute. Retiming
the tear, riding or stop requires coordinating sound as well as picture.

## Source identities and rights

`provenance.json` pins the accepted movie, original source manifest, selected
Build/Take/Artifact identities, extracted-frame parentage and copied inputs.
These are documentary facts. The current Project has no pointers to absent
original Build state and makes no claim that an imported clip was generated by
a new run. Duplicate provider deliveries, unused earlier entry sequences,
machine-specific scripts and production caches remain with the original owner.
The accepted final movie and selected generation inputs are retained here.

The sound entry uses the current `samples` render argument. That packaging
adaptation changes its length parameter's name, not the synthesis or event times;
the original and adapted hashes are recorded. See `../LICENSES.md` for the
preserved original rights statements and the contribution licence.
